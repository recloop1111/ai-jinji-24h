# Admin / 企業・運営管理画面 UX — AI人事24h

対象: `/client/**`（企業ユーザー）, `/admin/**`（運営）。思想 = **洗練された現代的 BtoB SaaS**。
最優先は **操作の迷わなさ**。次に 情報の理解速度 → 視認性 → 美しさ → 装飾。参考は Linear/Stripe/Notion/Vercel の"考え方"（コピー禁止）。
利用者は日本の採用担当者・中小企業担当者。**説明なしで迷わず使える**ことが最重要。

## レイアウトと情報設計
- サイドバー（現在地明示）+ メイン。既存 `ClientDashboardShell` / admin layout を再利用。
- **重要情報ほど視覚階層を上げる**（サイズ/太さ/位置/コントラスト）。1 画面 1 主目的。
- 情報密度は「詰め込み」ではなく「必要なものが速く読める」。**余白でグルーピング**、枠の乱用を避ける。
- 専門用語を必要以上に使わない（社内語/英略語を避け、採用担当者の言葉に）。

## Primary action / 操作設計
- **Primary は 1 画面に 1 つ**（乱立させない）。他は secondary/ghost。
- **破壊操作（削除・停止・不採用確定 等）は通常操作と視覚分離**（Danger 色 + 位置を離す）。主動線の隣に置いて誤爆させない。
- **操作結果は即 feedback**（保存成功 toast/インライン、楽観更新 + 失敗ロールバック）。「押したのに何も起きない」を作らない。
- **disabled の理由を必ず示す**（例: 「上限に達しています」「必須項目が未入力」をボタン近傍/ツールチップ+テキストで）。理由不明の disabled を作らない。

## フォーム
- **入力順序を自然に**（上→下、関連項目を近接、必須を前に）。label 必須・placeholder を label 代わりにしない。
- バリデーション: 送信時 + 必要ならフィールド離脱時。エラーは**該当フィールド直下**に「何が問題か + 直し方」。`aria-invalid`/`aria-describedby`。
- 破壊/確定前は**変更点を要約**して確認（設定変更・上限変更・確定請求 等）。重要変更は既存の設定用パスワード（`company_setting_password_hash`）フローを尊重。
- 保存中はボタンをローディング化（二重送信防止）。成功で明示 feedback。

## テーブル / 一覧（応募者一覧・請求 等）
- ヘッダは控えめ（`text-xs text-slate-500 uppercase`）、行 hover、行区切りは薄い罫線。
- **モバイルで横スクロール前提にしない**: 重要列（氏名/ステータス/日時/スコア等）を残し、残りはカード化 or 行展開。列の優先順位を決める。
- ステータスは全画面で同一表現（`lib/applicants/displayStatus.ts`）。数値右寄せ `tabular-nums`、空は `—`。
- 一括操作は選択状態を明示 + 破壊系は確認。ページャ/フィルタの適用状態を可視化。

## Status / バッジ（統一）
- 応募者: 面接中=blue / 完了=green / 途中離脱=amber / 準備中=slate（**色 + テキスト**）。導出ロジックを再利用し独自表現を作らない。
- 請求/停止/プラン等も意味色 + テキスト。**色だけで伝えない**。

## Empty / Loading / Error（管理画面文脈）
- Empty: 「まだ〇〇がありません」+ 次アクション（作成/招待/設定へ）。**ダミーを実データ風に見せない**（例: 会話ログ未接続なら「会話ログはまだありません」）。
- Loading: スケルトンで**レイアウトを跳ねさせない**。虚偽進捗を出さない。
- Error: 汎用文言 + 再試行。PII/生 message を出さない。権限エラーは「アクセス権限がありません」等の明確な文言。

## 認可 / データ境界（UI でも崩さない）
- 企業ユーザーは**自社スコープのみ**（company → applicant → interview → …）。UI から他社データを引ける導線/ID 直打ちを作らない。
- 運営(admin/super_admin)は全社閲覧可だが、破壊操作は特に慎重に（確認 + Danger）。
- service-role をクライアントへ出さない。ブラウザ直クエリは RLS 前提の読取のみ（既存方針）。

## 一貫性
- 同じ意味の要素（ボタン/ステータス/日付書式/金額表記）は**全画面で同じ表現**。新しい表現を場当たりに作らない。
- 金額は税別/税込・単位を明示（従量課金＝人数 × 単価）。プラン表記は企業側に custom/特別契約を出さない（「従量課金」+ 実単価のみ）＝既存仕様を UI でも厳守。

## Responsive（管理画面）
- 320–390px: サイドバー collapse、テーブル→カード、主要 CTA を固定/上部に。
- tablet: 2 カラムに再構成。
- 13" MacBook / Windows laptop: 標準。過度に広げず `max-w` で可読幅を保つ。
- large desktop: 中央寄せ + 余白。全幅の間延びを避ける。

## やらないこと（admin）
- 意味のない gradient / 過剰 shadow / カード in カード / border だらけ / 巨大タイトル乱用。
- AI っぽさのための紫グラデ。業務画面は落ち着いたブランドブルー + slate。
