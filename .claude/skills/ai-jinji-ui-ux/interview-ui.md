# 応募者 AI 面接 UX — AI人事24h

対象: `/interview/[slug]/**`（応募者フロー）。**管理画面とは別思想**。
最優先は **安心感**。次に 次に何をすればいいか分かる → 会話への集中 → デバイス状態の理解 → 視覚的な生命感。
応募者に「業務システムを操作している」と感じさせない。**緊張した応募者でも迷わない**こと。

## 大原則（面接中に常に満たす）
面接中はどの瞬間でも、応募者が一目で分かること：
1. **何が起きているか**（AIが話している/聞いている/考えている、接続中、終了処理中）
2. **自分が今話していいのか**（listening のときだけ「あなたの番」を控えめに提示）
3. **次に何をすればいいのか**（許可する/話す/待つ/再接続する/終了する）
- 面接中は**不要な情報を増やさない**。数値やメタ情報を並べない。1 画面 1 焦点（AI面接官）。

## デバイス（prepare & session）
- **マイク = 必須 / カメラ = 任意**。カメラ不可でも面接を止めない（`lib/interview/media.ts` の方針を UI で守る）。
- **権限拒否/デバイス不良で詰まらせない**: エラー種別ごとに日本語で「何が起きたか + どう直すか」+ 再試行。生 DOMException を出さない（`classifyMediaError`/`mediaErrorMessage` を使う）。
- prepare: マイクテスト（話しかけると進む）。カメラ不可時は「カメラなしで進む」を明示。開始ボタンの活性条件（マイク）を明確に、無効理由を近くに。
- session コントロール（左下等・固定）:
  - **マイク mute / カメラ ON-OFF は `track.enabled` で**（再取得しない）。状態は**アイコン + テキスト + `aria-pressed`**（色だけにしない）。
  - カメラ OFF 中は小窓を「カメラOFF」表示（凍結フレームを残さない）。
- **デバイス切断**（track ended / devicechange）: マイク切断は再接続案内（mock 時）。realtime 中は無音送出を続けず終了扱い（既存 `handleMicLost` 方針）。カメラ切断は小窓 OFF のみ（面接継続）。

## AI 面接官の状態表現（presence）
- 状態ソースは `interviewPhase`（connecting/idle/listening/thinking/speaking/ending）。**単一入口**（`setPhase`）で駆動。
- 状態は**アバターの見た目 + 状態ラベル（テキスト）**で表す（色/アニメだけにしない）。SR にも状態を伝える。
- **生命感**は breathing/リング/波形など控えめに。`prefers-reduced-motion` で必ず抑制。発光/派手さは"AI らしさの演出"ではなく状態の可読性のため。

## 現在質問 / 進捗 / 時間
- **現在質問**（AI発話テキスト）は読みやすく（`whitespace-pre-wrap break-words`, 長文はスクロール, `aria-live="polite"`）。
- **進捗** X/Y は mock の設問提示ベースのみ（realtime は index 不確定＝**発話数/turn 数で誤進捗を出さない**）。
- **経過/残り時間**は控えめに（`tabular-nums`）。時間警告は一度だけ穏やかに。

## iOS / Safari 自動再生
- AI 音声はユーザー操作起点で unlock（seam）。自動再生ブロック時のみ「タップして音声を有効にする」を出す（**realtime 実音声がある時だけ**・mock では出さない）。

## 終了 / 完了 / 途中終了 / 通信エラー
- **終了操作**は誤爆しにくく（確認は簡潔に「終了すると再開できません」）。デスクトップ右下 / モバイル下部固定など到達しやすい位置。
- 完了: 「面接を終了しています…」の**正直な短い interim**（虚偽の長い処理演出をしない）→ 完了画面。complete の実データ（所要/設問数）は interview_id 一致時のみ表示、無ければ非表示。
- 途中終了/キャンセル: 応募者向けの落ち着いた終了表示（管理画面へ遷移しない）。
- 通信/サーバエラー: 落ち着いた文言 + 可能なら再試行/やり直し導線。生 error/PII を出さない。フェールは mock へフォールバック等、応募者を"詰まらせない"。

## 端末別（面接は多くがスマホ縦）
- **スマホ縦（320–390px）を第一に**設計。固定コントロール（カメラ小窓・言語・進捗バー・終了バー）が本文と**重ならない**（既存の上部 clearance / 通常フロー配置の教訓を守る）。
- iOS Safari: autoplay/セーフエリア/100vh 問題に注意。Android Chrome: アプリ切替でのデバイス断。PC Chrome/Edge/Safari: 標準。
- 会話テキスト・ボタンが崩れない（`break-words`・十分なタッチ target・横スクロールなし）。

## トーン / ビジュアル
- 背景は落ち着いた暗色（`slate-900→slate-800`）で集中を促す（管理画面と違い例外的にダーク）。
- 過剰装飾・情報過多を避け、**AI面接官と現在質問に視線が集まる**構図。
- 色だけで状態を伝えない（mute/OFF/接続状態はテキスト/アイコン併用）。

## やらないこと（interview）
- 面接中に不要な数値/メタ/広告的要素を足す。業務システム的な密なUI。
- 未実装機能を操作可能に見せる（例: 録画未実装なら"録画中"と偽らない）。
- 発話数を進捗の権威にする / 生の Realtime イベントを UI に直結する（seam 経由）。
